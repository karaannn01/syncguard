The Problem in Field Operations

Why Traditional Apps Fail in the Field

1. Network Blackouts

Turbine basements, offshore rigs, and utility sub-levels operate with zero cellular signal. Traditional web apps freeze or throw fatal network errors.

2. "Last-Write-Wins" Destruction

Standard syncing relies on device clocks. Whoever syncs last blindly obliterates prior work, causing silent loss of safety audits and sensor calibrations.

3. Generic To-Do App Trap

Field service is not a personal to-do list. Multiple technicians touch the same asset concurrently. Concurrency must be governed mathematically.

Engineering Foundation

Client-Server Dual Concurrency Architecture

Client Layer (Dexie IndexedDB)

  • ✓ 7 Dedicated Stores: tasks, checklists, outbox, conflicts, sync_metadata, users, activity_logs.
  • ✓ Local-First Write: Mutations persist to IndexedDB in <5ms. Zero UI latency.
  • ✓ Persistent Outbox: Serialized mutations withstand reboots, page refreshes, and app closures.

Backend Layer (Node.js + PostgreSQL)

  • ✓ Monotonic Versioning: Every synchronizable record tracks an immutable integer version.
  • ✓ Strict Idempotency: Unique operationId caching guarantees duplicate packets cannot double-mutate.
  • ✓ Dual Storage Engine: Native PostgreSQL with zero-config SQLite embedded fallback.
Core Innovation

Algorithmic Conflict Detection & Auto-Merging

1. Exact Version Match

baseVersion === serverVersion: Apply mutation cleanly, version + 1.

2. Disjoint Fields

Different fields modified: Auto-Merge automatically without human friction!

3. Colliding Field Values

Same field changed to different values: Safe conflict creation in Conflict Center.

Rule: Never implement blind Last-Write-Wins. Delete-vs-Edit and concurrent value collisions are preserved for operator review.
The Live Demonstration

The Official Hackathon Scenario in Action

Step 1 Task 7701 (CNC Milling Unit #4) starts at baseline Version 7.
Step 2 Device A (Toughbook) goes offline: status = COMPLETED, quantity = 50.
Step 3 Device B (Tablet) goes offline: status = IN_PROGRESS, quantity = 45.
Step 4 Device A reconnects and syncs $\rightarrow$ Server advances cleanly to Version 8.
Step 5 Device B reconnects with base v7 $\rightarrow$ Server flags conflict! Disables blind overwrite.
Step 6 Operator opens Conflict Center $\rightarrow$ Resolves via Side-by-Side Merge $\rightarrow$ advances to Version 9.
